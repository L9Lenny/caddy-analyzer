Log Sources Guide

Stream and analyze Caddy v2 access logs from files, stdin, Docker, Kubernetes, and systemd
Overview Installation Log Sources Subcommands Threat Detector TUI & HTML Reports

1. Local Log Files & Glob Patterns

Read from single or multiple Caddy log files using path globs:

# Single file
caddy-analyze /var/log/caddy/access.log

# Multiple files using wildcard globs
caddy-analyze /var/log/caddy/*.log

# Auto-discovery mode (runs against ./access.log, ./caddy.log, or /var/log/caddy/access.log)
caddy-analyze

2. Standard Input (Pipes)

Pipe log streams directly into caddy-analyze via standard input using -:

# Pipe from cat or zcat (compressed logs)
zcat /var/log/caddy/access.log*.gz | caddy-analyze -

# Pipe from custom command stream
docker logs -f my-caddy | caddy-analyze -

3. Docker Containers (docker://)

Stream logs directly from a running Docker container without needing file access on host:

# Run static analysis against Docker container logs
caddy-analyze docker://my-caddy-container

# Live streaming view from Docker
caddy-analyze tail docker://my-caddy-container

4. Kubernetes Pods (k8s://)

Stream logs directly from Kubernetes pods (uses kubectl logs under the hood):

# Read logs from pod in current namespace
caddy-analyze k8s://caddy-pod-xyz

# Specify namespace using -n or --namespace
caddy-analyze k8s://caddy-pod-xyz -n production

5. Systemd Journalctl (journalctl://)

Read directly from systemd unit logs when Caddy runs as a system service:

# Read systemd unit log
caddy-analyze journalctl://caddy.service
