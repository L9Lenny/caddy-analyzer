Running Threat Detection

Enable the threat detector using the --detect / -d flag:

caddy-analyze --detect /var/log/caddy/access.log

Detection Rule Categories

Before matching rules, the detector unescapes URL encoding to prevent encoding evasion techniques (e.g. %2e%2e%2f converted to ../):

Threat Category Patterns & Attack Vectors
SQL Injection (SQLi) UNION SELECT, SELECT FROM, OR 1=1, information_schema, pg_sleep(), Benchmark()
Path Traversal / LFI ../, %2e%2e%2f, /etc/passwd, /proc/self/environ, php://filter, file:///
Cross-Site Scripting (XSS) <script>, javascript:, onerror=, alert(, %3Csvg
Remote Code Execution (RCE) /bin/sh, powershell, whoami, cat /etc/, eval(base64
Sensitive File Discovery .env, .git/config, wp-config.php, id_rsa, .aws/credentials
Admin Interface Probes /phpmyadmin, /actuator/env, /wp-login.php, /console/
Scanner Tools sqlmap, nikto, dirbuster, gobuster, nmap, burp suite, zap

Real-Time Auto-Blocking Guard Daemon

The guard subcommand monitors log streams and automatically adds offending IPs to Linux iptables DROP rules when attack thresholds are exceeded:

sudo caddy-analyze guard --limit 50 --window 1m docker://my-caddy
